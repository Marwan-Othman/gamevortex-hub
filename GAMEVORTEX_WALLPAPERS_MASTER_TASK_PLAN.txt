==================================================
IMPORTANT WORKING RULES
==================================================

1. لا تبدأ بتعديل أي ملف قبل فحص المشروع الحالي وفهم بنيته.
2. المشروع الحالي هو Next.js + TypeScript + Prisma + PostgreSQL.
3. يوجد بالفعل نظام Wallpapers في المشروع، لذلك لا تعيد بناء شيء موجود قبل فحصه.
4. حافظ على الميزات الحالية التي تعمل بشكل صحيح.
5. لا تحذف أي نظام موجود إلا إذا ثبت أنه غير مستخدم أو مكسور، وبعد توثيق السبب.
6. لا تفترض أسماء ملفات أو Models أو APIs. افحصها أولًا.
7. لا تستخدم API Keys أو Secrets داخل Git.
8. جميع صلاحيات VIP يجب أن تكون Server-Side، وليس مجرد إخفاء أزرار في الواجهة.
9. SUPER_ADMIN / OWNER يجب أن يحصل على صلاحيات Owner الحالية الموجودة في المشروع.
10. لا تستخدم صورًا محمية بحقوق النشر أو تستخرج صورًا من تطبيقات أخرى بدون ترخيص.
11. أي صورة يتم إدخالها إلى النظام يجب أن يكون مصدرها وترخيص استخدامها معروفين.
12. لا تضع آلاف الصور داخل GitHub.
13. استخدم Storage/CDN مناسبًا للصور، وقاعدة البيانات تحفظ metadata وروابط الملفات.
14. كل مرحلة يجب اختبارها قبل الانتقال للمرحلة التالية.
15. لا تعتبر المهمة مكتملة بمجرد أن يعمل الكود محليًا. يجب اختبار Mobile وDesktop وAuthentication وVIP وSecurity.
16. عند تعديل ملف موجود، حافظ على بقية وظائفه ولا تستبدل المنطق السليم بلا سبب.
17. لا تنشئ Duplicate APIs أو Duplicate Database Models إذا كان النظام الحالي يحتوي عليها.
18. إذا وجدت تعارضًا بين النظام الحالي وهذه الخطة، افحصه أولًا وحدد الحل الأفضل قبل التنفيذ.
19. لا تخمّن. إذا كانت معلومة غير موجودة في المشروع، ابحث عنها في الملفات أو اطلب توضيحًا.
20. الهدف هو أعلى دقة واستقرار ممكن، مع تقليل الأخطاء قبل الانتقال بين المراحل.

PHASE 2 — FREE / VIP WALLPAPER SYSTEM
==================================================

TASK 2.1 — FREE/VIP Flag
إضافة نظام isVip:
false = FREE
true = VIP
ليس كل المحتوى VIP.

TASK 2.2 — Server-Side VIP Protection
حماية تحميل Wallpaper VIP من السيرفر.
User → Request Download → Authentication → Wallpaper check → VIP entitlement → FREE allow / VIP require active VIP / SUPER_ADMIN allow → Download.
لا تعتمد على localStorage أو frontend state أو hidden buttons.

TASK 2.3 — VIP Expiration
عند انتهاء VIP:
- يفقد المستخدم الوصول إلى VIP Wallpapers.
- لا تحذف بياناته أو نقاطه أو Favorites.
- FREE Wallpapers تبقى متاحة.
- SUPER_ADMIN / OWNER يستمر وفق نظام Owner.

TASK 2.4 — VIP UI
إظهار VIP badge للخلفيات المحمية، وتوجيه المستخدم غير VIP إلى صفحة VIP، والسماح بالتحميل للمستخدم VIP.

EXECUTION PROTOCOL
==================================================

قبل كل تعديل:
1. اقرأ الملفات الحالية.
2. افهم dependencies.
3. حدد الملفات المتأثرة.
4. نفذ التعديل.
5. شغّل الاختبارات المناسبة.
6. راجع النتائج.
7. أصلح الأخطاء.
8. ثم انتقل للمرحلة التالية.

DO NOT:
- Rewrite the entire project.
- Delete working systems.
- Duplicate existing APIs.
- Duplicate existing database models.
- Hardcode secrets.
- Trust client-side VIP checks.
- Copy copyrighted wallpaper libraries without permission.
- Put thousands of images in GitHub.
- Mark the project complete without testing.

GOAL:
إنشاء نظام GameVortex Wallpapers احترافي وقابل للتوسع يحتوي على FREE + VIP + AI + Video Wallpapers، مع إدارة كاملة من Admin، وحماية Server-Side، ودعم Mobile/Desktop، وقابلية التوسع إلى آلاف الصور، مع الحفاظ على الأنظمة الحالية في GameVortex وعدم كسرها.
