مواصفات تطوير المشروع الحالي — Production Specification

1. فكرة المشروع
- تطوير المشروع الحالي نفسه، وليس إنشاء مشروع جديد أو Demo منفصل.
- إجراء فحص شامل للمشروع قبل أي تعديل، مع المحافظة على الكود والبيانات الجيدة.
- دعم العربية RTL والإنجليزية LTR مع تبديل اللغة.
- تصميم 3D Glassmorphism خرافي وفاخر كهوية بصرية أساسية للمشروع، مع طبقات زجاجية شفافة، عمق ثلاثي الأبعاد، إضاءة واقعية، Refraction، Blur، Depth، Soft Shadows، Volumetric Glow، Floating Cards، Parallax، Micro-interactions، وواجهة مستقبلية راقية، مع الحفاظ على الأداء وReduced Motion.
- Responsive للهاتف والتابلت واللابتوب وسطح المكتب.

2. Audit شامل قبل التطوير
فحص:
- الصفحات وComponents.
- قاعدة البيانات وEntities.
- Authentication وRoutes وAPIs.
- RBAC والصلاحيات.
- التصميم والبيانات الموجودة.
- عدم إعادة بناء المشروع من الصفر.
- عدم حذف البيانات بدون Migration آمنة.

3. المستخدمون والصلاحيات
الأدوار:
- SUPER_ADMIN
- STAFF
- USER
- يوجد SUPER_ADMIN واحد فقط وهو مالك المشروع المحدد في ملف المشروع.
- حماية الصلاحيات Server-side، وليس عبر إخفاء عناصر الواجهة أو localStorage/React State فقط.

المناطق الحساسة:
- /admin
- /api/admin
- Wallet
- Payments
- Withdrawals
- Points
- Downloads

الاستجابات:
- 401 للمستخدم غير المسجل.
- 403 للمستخدم المسجل غير المصرح له.

منع تعديل:
- الدور.
- Owner status.
- الرصيد.
- النقاط.
- الأسعار.
- المكافآت.

الحماية من:
- IDOR.
- Privilege Escalation.
- XSS.
- CSRF.
- SQL/NoSQL Injection.
- Replay attacks.
- Rate abuse.
- Secret exposure.

تسجيل جميع العمليات الحساسة في Audit Logs.

4. قاعدة البيانات
- استخدام Prisma/PostgreSQL إذا كان متاحًا.
- إذا لم يكن متاحًا، تحويل التصميم إلى قاعدة/خدمة موثوقة أخرى مناسبة للبيئة.
- النماذج المطلوبة:
  User, Wallet, OwnerWallet, Game, App, GiftCard, Purchase, Review,
  DownloadHistory, PointHistory, WithdrawalRequest, Notification, Task,
  PaymentTransaction, AuditLog, ProductImage, Payout, Settings.
- استخدام Decimal أو integer cents للأموال، وعدم استخدام Float.
- Unique Constraints.
- Atomic Transactions.
- Idempotency.

5. الألعاب والتطبيقات
يجب أن يكون الكتالوج حقيقيًا وليس Fake Data.

كل Game يتضمن:
- عنوان عربي وإنجليزي.
- Slug.
- وصف.
- المنصة.
- النوع والتصنيف.
- السعر والخصم.
- Rewards.
- صورة الغلاف وScreenshots.
- الحجم.
- عدد التحميلات.
- التقييم.
- الرابط الرسمي.
- مصدر التحميل.
- حالة المصدر.

حالات المصدر:
- VERIFIED
- NEEDS_SOURCE
- PENDING_REVIEW
- UNPUBLISHED

RAWG يستخدم للـMetadata فقط، وليس مصدرًا لملفات الألعاب.

- دعم Batch Import/Upsert لـ500+ لعبة حقيقية عند توفر 500+ مصدر حقيقي موثوق.
- لا يجوز نشر لعبة بدون مصدر موثوق.
- منع Picsum وUnsplash كصور تمثيلية للألعاب.
- منع example.com والروابط الوهمية.

6. نظام Download
إنشاء:
- /api/download

ويكون محميًا بـ:
- Authentication.
- Authorization.
- Source Verification.
- Duplicate Protection.

التحميل المباشر فقط للملفات:
- المرخصة.
- المملوكة/المصرح بتوزيعها.
- الموجودة على Storage/CDN موثوق.

يفضل Signed URLs أو Secure Download Endpoint.

ممنوع:
- Fake Download.
- Dummy Blob.
- data:text.

إذا لم يوجد مصدر قانوني:
- عرض NEEDS_SOURCE / Official Store بدل الادعاء بوجود تحميل مباشر.

عند التحميل الصحيح:
- تسجيل DownloadHistory.
- زيادة downloadsCount.
- إعطاء النقاط مرة واحدة.
- تسجيل PointHistory.
- تسجيل AuditLog.
- إنشاء Notification.

7. نظام النقاط
المستويات:
- FREE: 1000 نقطة = 5؛ أول تحميل مجاني = +5 نقاط.
- VIP: 500 نقطة = 5؛ التحميل المجاني = +5.
- OWNER: 30 نقطة = 0.50؛ التحميل المجاني = +500.

كما يوجد:
- pointsReward للمستخدم.
- ownerPointsReward للمالك.

- محمية من التكرار والتلاعب.

22. AI & SMART PLATFORM UPGRADE
================================

إضافة طبقة AI متكاملة داخل GameVortex Hub مع الحفاظ على المشروع الحالي وعدم إنشاء مشروع منفصل.

22.1 AI Assistant داخل المنصة
- AI Assistant داخل الواجهة الرئيسية وصفحات الألعاب والتطبيقات وحساب المستخدم.
- دعم العربية والإنجليزية وRTL/LTR.
- الإجابة اعتمادًا على بيانات المنصة الحقيقية.
- منع اختلاق الألعاب والأسعار والروابط والمخزون والعروض.
- Loading/Error/Retry وClear Chat.
- Rate Limiting وتسجيل استخدام آمن.
- عند عدم وجود مزود AI حقيقي: NOT_CONFIGURED بدل Fake AI.

22.2 AI Smart Search
- بحث ذكي يفهم اللغة الطبيعية بالعربية والإنجليزية.
- تحويل الطلبات الطبيعية إلى فلاتر Server-side.
- Relevance + Rating + Popularity + Availability.
- دعم المنصة والنوع والسعر والتقييم والإصدار والحجم.
- حماية من Prompt Injection وInput Abuse.
- Debounce وCaching عند الحاجة.

22.3 AI Recommendations
- نظام توصيات شخصي لكل مستخدم.
- الاستفادة من المشاهدات والمفضلة وWishlist والتنزيلات والتقييمات والبحث والمنصة والتصنيف.
- أقسام Recommended For You وBecause You Viewed وSimilar Games وYou May Also Like.
- Fallback إلى Popular/Trending عند نقص البيانات.
- التوصيات من المنتجات المنشورة والحقيقية فقط.
- إمكانية تعطيل التخصيص.

22.4 AI Game Discovery
- اكتشاف الألعاب بالذكاء الاصطناعي من الكتالوج الحقيقي.
- دعم Platform وGenre وPrice وRating وRelease Date وSize وAvailability.
- إظهار سبب التوصية باختصار.

22.5 AI Admin Analytics
- تحليل البيانات الحقيقية للتحميلات والمشتريات والإيرادات والمستخدمين وVIP والنقاط والبطاقات والمراجعات والترند.
- كشف التغيرات غير الطبيعية واقتراح مؤشرات للمراجعة.
- لا يسمح للـAI بتعديل الأموال أو النقاط أو الصلاحيات مباشرة.

22.6 AI Content Moderation
- مراجعة Reviews والمحتوى الذي ينشئه المستخدم.
- الحالات SAFE / NEEDS_REVIEW / REJECTED.
- اكتشاف Spam وAbuse ومحاولات إدخال تعليمات ضارة.
- Human Review عند الحاجة.
- Audit Logs.

22.7 AI Safety & API Protection
- API Keys في Server-side فقط.
- Authentication وAuthorization وRate Limiting.
- حماية Prompt Injection وTool Injection.
- عدم إرسال كلمات المرور أو Private Keys أو Seed Phrases أو البيانات الحساسة إلى AI.
- Allowlist للأدوات.
- Cost Controls وRequest Limits وTimeouts.

41. CONTENT MODERATION WORKFLOW

52. HOMEPAGE RANKINGS + DYNAMIC MOST PLAYED / TOP RATED
=========================================================

إضافة قسم رئيسي مخصص في الصفحة الرئيسية لعرض الألعاب الأعلى تقييماً والأكثر لعباً، مع تحديث تلقائي اعتماداً على بيانات الاستخدام الحقيقية من قاعدة البيانات، وليس بيانات وهمية أو قوائم ثابتة.

52.1 واجهة القسم
------------------
- قسم واضح في الصفحة الرئيسية بعنوان قابل للتعريب مثل: "الأعلى تقييماً" و"الأكثر لعباً".
- تبويبات أو شرائح مستقلة:
  1. الأعلى تقييماً Top Rated.
  2. الأكثر لعباً Most Played.
  3. الأكثر رواجاً Trending.
  4. صاعد بسرعة Rising Fast.
  5. جديد ومميز New & Featured.
- بطاقات ألعاب متجاوبة Desktop / Tablet / Mobile.
- صورة الغلاف، الاسم، المنصة، النوع، التقييم، عدد التقييمات، وعدد مرات اللعب/التشغيل بحسب البيانات المتاحة.
- زر مشاهدة التفاصيل، وزر إضافة إلى المفضلة/Wishlist عند توفر الصلاحية.
- Skeleton Loading وEmpty State وError State.
- دعم RTL/LTR وإمكانية الوصول ولوحة المفاتيح وReduced Motion.

52.2 منطق الترتيب الديناميكي
-----------------------------
- Top Rated يعتمد على متوسط التقييم مع مراعاة عدد التقييمات لتقليل تأثير لعبة حصلت على تقييمات قليلة جداً.
- Most Played يعتمد على أحداث اللعب/التشغيل الحقيقية المسجلة Server-side.
- Trending يعتمد على معدل النمو في اللعب والتفاعل خلال فترة زمنية حديثة مقارنة بالفترة السابقة.
- يمكن احتساب الوزن من عدة مؤشرات حقيقية مثل play events وviews وratings وfavorites وwishlist، وفق سياسة واضحة قابلة للضبط من Admin.
- لا يسمح للواجهة Frontend بتعديل ترتيب الألعاب مباشرة.
- كل الحسابات الحساسة تتم Server-side.
- تطبيق حد أدنى لعدد التقييمات قبل إدراج اللعبة في Top Rated إذا كان ذلك مطلوباً من إعدادات النظام.
- منع التلاعب بالتقييمات أو اللعب المتكرر المصطنع عبر Rate Limiting وAnti-Abuse وAnomaly Detection.

52.3 التحديث التلقائي
----------------------
- تحديث النتائج عند تسجيل أحداث جديدة مؤثرة في الترتيب.
- استخدام Cache آمن مع TTL مناسب لتقليل ضغط قاعدة البيانات.
- Invalidation عند تغير التقييمات أو أحداث اللعب المهمة.
- إمكانية تحديث القسم دورياً دون إعادة تحميل الصفحة بالكامل.
- عند فشل التحديث، يتم الاحتفاظ بآخر نتيجة سليمة مع إظهار حالة مناسبة دون اختلاق بيانات.

52.4 قاعدة البيانات وواجهات API
--------------------------------
- استخدام الجداول/Models الحالية للألعاب والمستخدمين والتقييمات والتفاعلات عند إمكانية ذلك.
- عدم إنشاء Model أو API مكرر إذا كان الموجود يمكن توسيعه بأمان.
- تسجيل Play Event بطريقة Idempotent ومحمية من التكرار غير الطبيعي.
- Endpoint قراءة مخصص للترتيبات الديناميكية يمكنه دعم:
  - category=top-rated
  - category=most-played
  - category=trending
  - category=rising
- دعم pagination وlimit وplatform وgenre وtimeRange عند الحاجة.
- حماية API من scraping المفرط وRate Limiting.
- عدم كشف بيانات المستخدمين الشخصية ضمن إحصاءات القسم.

52.5 لوحة الإدارة
------------------
- إعدادات للتحكم في فترة التحليل، الحد الأدنى للتقييمات، أوزان المؤشرات، TTL للـCache، وعدد الألعاب المعروضة.
- معاينة أسباب ظهور اللعبة في الترتيب.
- سجلات Audit عند تعديل خوارزمية الترتيب أو إعداداتها.
- منع Admin/Staff غير المصرح لهم من تعديل إعدادات الترتيب الحساسة.

53. QURAN RECITERS / AUDIO VOICE SYSTEM
========================================

إضافة نظام أصوات قراء عالميين داخل الميزة الصوتية الموجودة في المشروع، مع إمكانية اختيار القارئ وتغييره بسهولة، بشرط استخدام مصادر صوتية مرخصة أو Integrations قانونية فعلية وعدم تضمين ملفات صوتية محمية بحقوق غير مصرح بها.

53.1 مكتبة القراء
------------------
إتاحة قائمة قابلة للتوسعة من القراء، ومن أمثلة القراء الذين يمكن دعمهم عند توفر مصدر قانوني/ترخيص مناسب:
- الشيخ مشاري راشد العفاسي.
- الشيخ عبد الباسط عبد الصمد.
- الشيخ عبد الرحمن السديس.
- الشيخ ماهر المعيقلي.
- الشيخ ياسر الدوسري.
- الشيخ سعد الغامدي.
- الشيخ محمد صديق المنشاوي.
- الشيخ محمود خليل الحصري.
- الشيخ سعود الشريم.
- الشيخ فارس عباد.
- الشيخ هاني الرفاعي.
- الشيخ إدريس أبكر.
- الشيخ ناصر القطامي.

ملاحظة تنفيذية: لا تتم إضافة أي تسجيل فعلي أو رابط صوتي إلا من Provider حقيقي ومصدر قانوني موثوق، ويتم حفظ بيانات الترخيص/المصدر في Server-side Configuration عند الحاجة.

53.2 واجهة اختيار القارئ
-------------------------
- صفحة/نافذة اختيار القارئ.
- صورة أو أيقونة تعريفية عند توفرها بشكل قانوني.
- اسم القارئ.
- اللغة/الرواية/الجودة إذا كانت متاحة من المصدر.
- زر Preview لتجربة مقطع قصير من المصدر المصرح به.
- زر Select/اختيار.
- مؤشر للقارئ الحالي.
- بحث وفرز حسب الاسم.
- إمكانية تمييز القراء المفضلين.

53.3 تغيير صوت القارئ
----------------------
- زر "تغيير القارئ" ظاهر داخل مشغل الصوت.
- تغيير القارئ دون فقدان موضع التشغيل الحالي إذا كان المصدر يدعم ذلك.
- حفظ القارئ المفضل Server-side للمستخدم المسجل، وLocal Preference للزائر عند الحاجة.
- مزامنة الاختيار بين الأجهزة للمستخدم المسجل.
- استعادة آخر قارئ مستخدم عند فتح المشغل.
- إعداد افتراضي قابل للتغيير من Settings.

53.4 مشغل الصوت
----------------
- Play / Pause.
- Previous / Next.
- شريط تقدم قابل للسحب.
- مستوى الصوت.
- سرعة التشغيل عند دعمها من المشغل.
- Repeat / Auto Next.
- إظهار اسم السورة/المقطع والقارئ.

53.5 Backend / Security / Privacy
----------------------------------
- لا يتم وضع مفاتيح API أو Secrets داخل Frontend.

- دعم حذف تفضيل القارئ وإدارة الخصوصية.

54. UNIFIED ACCEPTANCE CRITERIA FOR RANKINGS + AUDIO
====================================================
- القوائم الأعلى تقييماً والأكثر لعباً تعتمد على بيانات حقيقية من Database.
- لا توجد Fake Statistics أو Fake Reviews أو Fake Play Counts.
- ترتيب الألعاب يتغير تلقائياً عند تغير البيانات المؤثرة.
- لا يمكن للمستخدم تعديل الإحصاءات أو ترتيب الألعاب من Frontend.
- جميع العمليات الحساسة Server-side.
- لا توجد API Keys أو Secrets في Frontend.
- قسم الصفحة الرئيسية Responsive وRTL/LTR وAccessible.

- 30 نقطة = 1 USD للمالك فقط.
- النظام يرفض أي طلب أقل من 15 نقطة.
- النظام يحسب القيمة Server-side.
- لا يستطيع المستخدم العادي استخدام Owner Withdrawal.
- لا يمكن خصم النقاط مرتين.
- إذا فشل الدفع تعاد النقاط المحجوزة.
- لا يتم تسجيل السحب كناجح قبل Confirmation حقيقي.
- جميع عمليات السحب مسجلة في Owner Ledger وAuditLog.
