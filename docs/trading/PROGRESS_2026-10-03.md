## Completed

- Confirmed the durable live-order minimum is **$1**; there is no hard-coded global maximum in the live-order state. Higher amounts remain subject to Risk Manager, allocation, exposure, exchange and available-balance limits.
- Added `lib/trading/live-execution-readiness.ts` as the safe integration contract for the production sequence.
- Added `lib/trading/live-execution-readiness.test.ts` covering live-flag and production-readiness boundaries, protected SELL OCO planning, and the $1 minimum.
- Added `lib/trading/live-production-executor.ts` as the server-side production execution coordinator. It:
  - requires a consumed owner approval;
  - re-checks the trading control/emergency-stop boundary;
  - requires a clean Binance production preflight;
  - re-checks the stored Shariah asset through the reviewed-policy gate;
  - re-evaluates the current Risk Manager configuration against the approval snapshot;
  - creates a durable idempotent live-order intent before provider submission;
  - reconciles provider state by immutable client order id;
  - fails closed to `UNKNOWN` on ambiguous provider failures;
  - requires a confirmed fill before submitting the protective OCO;
  - verifies both protective OCO client-order identities before marking the order `PROTECTED`;
  - trips the circuit breaker on order/protection failures;
  - writes audit events for critical live-order transitions.
- Added `lib/trading/binance-live-symbol-rules.ts` and tests. Live execution validates current Binance Spot symbol status and exchange constraints before submission, including minimum notional and protected-exit quantity/price filters.
- Added a dedicated protected-exit leg status contract to the exchange adapter and Binance production adapter.
- Added durable live-exit settlement state to `TradingLiveOrder`.
- Added `lib/trading/live-exit-settlement.ts` for fail-closed OCO leg reconciliation. A position is closed only after the provider confirms a single completed exit leg, the opposite OCO leg is terminal/canceled, the exit quantity covers the confirmed entry quantity, and the exit quote value is available.
- Added gross realized P/L calculation from the confirmed entry and exit quote quantities. The result is stored as `EXCHANGE_CLOSED_PENDING_WALLET`; it is deliberately **not** credited to the GameVortex wallet yet.
- The live executor now re-checks protected exits instead of returning immediately when an order is already `PROTECTED`.

## Safety boundary

The production live flag remains disabled. The production coordinator is therefore not executable against Binance while the flag is false. The coordinator also stops on the TradingControl emergency stop, an uncleared circuit breaker, an unreviewed Shariah policy, or a failed Binance production preflight.

Exchange closure, realized P/L, and internal wallet settlement remain separate accounting events. A provider exit fill is not treated as a wallet credit by itself.

## Important external constraint

The application-level minimum remains **$1**, but Binance can impose symbol-specific minimum-notional and quantity/price filters. Those checks are now part of the live execution path. Therefore a requested $1 trade is still the application's minimum, but a specific Binance symbol can legitimately reject it if its current exchange rules require a larger notional.
